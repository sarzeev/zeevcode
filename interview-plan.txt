# 4. PAYMENT PROVIDER

Use **Razorpay Checkout + Razorpay Orders API**.

Payment amount MUST be controlled by the backend.

Price:

```text
₹99 = 9900 paise
```

The frontend must never be allowed to choose the amount.

Backend flow:

```text
Frontend
   ↓
POST create order
   ↓
Backend creates Razorpay order for ₹99
   ↓
Frontend opens Razorpay Checkout
   ↓
Razorpay payment
   ↓
Frontend sends payment details to backend
   ↓
Backend verifies Razorpay signature
   ↓
Backend verifies order/payment details
   ↓
Create Interview Prep entitlement
   ↓
Return success
```

Never grant access merely because the frontend reports success.

# 7. BACKEND API

Follow existing ZeevCode controller/service conventions.

Use equivalent endpoints if a payment architecture already exists.

Suggested:

```text
POST /api/payments/interview-prep/order
POST /api/payments/interview-prep/verify
GET  /api/payments/interview-prep/status
```

### Order endpoint

Requirements:

* authenticated user required
* server creates ₹99 Razorpay order
* persist order before/around Razorpay creation according to safe transaction handling
* return only necessary checkout data
* never accept arbitrary amount from frontend

### Verify endpoint

Accept the Razorpay checkout response fields.

Server must:

* validate authenticated user
* validate the order belongs to that user
* validate expected amount/currency
* verify Razorpay payment signature using the secret
* ensure payment/order state is valid
* mark payment verified
* create entitlement transactionally/idempotently
* return success only after backend verification

### Status endpoint

Return whether the authenticated user owns:

```text
INTERVIEW_PREP
```
